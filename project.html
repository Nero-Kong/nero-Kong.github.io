Project One

A small but carefully built tool for distributed model serving. Used by several teams in production. This page documents what it is, why it exists, and how it works.

Visit live ↗ View on GitHub
⌘

— Overview

This project began as a quiet experiment to understand why our distributed inference setup was so brittle under realistic load. What started as a debugging tool turned into a full reimplementation of the serving layer, now adopted across several teams and handling production traffic at scale.

The core idea is simple: instead of treating each request as independent, we batch by structural similarity and route through a learned scheduling layer. The result is roughly 3.4× throughput improvement on long-context workloads with no quality regression.

The interesting bottleneck is rarely where you expect it. Most of our latency turned out to live in scheduling, not compute. — from the design doc

— Architecture

The system has three pieces. A request shaper that normalizes incoming requests into a canonical form. A scheduler that batches by predicted compute cost. And a worker pool that runs the actual model with adaptive memory allocation.

The scheduler is the most interesting piece. It uses a small learned model trained on production traces to predict per-request cost before the request is dispatched. This lets us pack batches more aggressively without risking out-of-memory failures.

A full architecture write-up is available in the technical report.

— Outcomes

Deployed to production in March 2026. Currently handling the majority of long-context inference traffic at our company. Adopted by three additional teams. Open-sourced as a reference implementation in October 2026.
